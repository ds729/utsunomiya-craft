# SPEC — Utsunomiya Craft

## 1. 目的
JR宇都宮駅（栃木県宇都宮市）周辺の**実際の地図データ**から、マインクラフト風（1ブロック=1m）のボクセル世界を生成し、ブラウザ上で**一人称視点で自由に歩き回れる**個人用アプリを作る。

- 主目的：「知っている街を、ブロックの世界として歩く」体験
- 個人利用。公開する場合もGitHub Pagesの静的ホスティングのみ
- 名称は仮に **Utsunomiya Craft**

## 2. データソースと方針
| 用途 | データ | 備考 |
|---|---|---|
| 道路・線路・水域・公園・建物外形・POI名 | **OpenStreetMap**（Overpass API） | 一度取得して `data/raw/` にキャッシュ。実行のたびに再取得しない。タイムアウト時はbboxをタイル分割 |
| 建物の高さ（精度向上） | **PLATEAU 3D都市モデル 宇都宮市（2023年度版を優先、無ければ2020年度版）** | G空間情報センターで配布、CityGML。商用含め無償利用可。**Phase 2で導入**。生データはコミットしない |
| 標高（任意） | 国土地理院 標高タイル（DEM） | **Phase 3**。Phase 1〜2は平坦（y=0） |

- Phase 1は**OSMのみ**で完結させる。建物高さは `height` → `building:levels`×3m → 種別ごとの既定値（住宅6m、商業12m等）の順
- 中心座標：JR宇都宮駅。**OSMの `railway=station` `name=宇都宮` のノードから取得して確定**する（推測値を直書きしない）
- 範囲：中心から半径 `RADIUS_M = 1000`（2km四方）を初期値とし、`config` で変更可能にする。東武宇都宮駅・大通り方面（西へ約2km）まで伸ばす場合は東西のみ拡張できる設計にする

## 3. アーキテクチャ

### 3.1 加工済みデータ（1m解像度・ラスタ）
座標系は、中心を原点とするローカルメートル座標。**+x=東、-z=北**。

| ファイル | 型 | 内容 |
|---|---|---|
| `ground.bin` | Uint8 | 地表材質ID（草地／土／アスファルト／歩道／線路バラスト／水／公園／広場タイル／駐車場…） |
| `bld.bin` | Uint8 | 建物高さ[m]（0=建物なし。上限 `MAX_H=96` でクランプ） |
| `bldtype.bin` | Uint8 | 建物種別ID（壁の色味・質感の選択用） |
| `deck.bin` | Uint8 | 高架構造（ペデストリアンデッキ・橋・立体交差）の下面高さ[m]（0=なし）。厚み1ブロックの床板として扱う |
| `world.json` | JSON | 原点の緯度経度、サイズ、解像度、POI一覧（名前・種別・座標）、ライセンス表記文 |

- 道路幅は `width`/`lanes` タグがあれば使用、無ければ `highway` 種別ごとの既定幅（primary 14m / secondary 10m / tertiary 8m / residential 6m / service 4m / footway 2m）
- 主要道路（secondary以上）の両側に幅2mの歩道を自動付与（`sidewalk=no` は除く）
- `tunnel=yes` は描画しない。`bridge=yes` かつ `layer>=1` は `deck.bin` に書く
- 建物は `building` の way と、`type=multipolygon` の relation（外周・内周）の両方を処理。`building:part`（駅ビル等）は高さ違いを反映
- ポリゴン塗りは偶奇規則（even-odd）のスキャンライン方式で自前実装

### 3.2 実行時のボクセル世界
- **チャンク 16×16（x,z）× 高さ約100**、プレイヤー周辺のチャンクだけを**ストリーミング生成**。チャンク生成は「ラスタ→ボクセル配列」の純関数
  - y=0 が地表面。その下は土3層＋最下層に岩盤
  - 建物は地表から `bld` の高さまで柱状に充填し、最上段を屋根材、その他を壁材に
  - 壁は3mごとに窓の段（フロア表現）をテクスチャで表現。色味は `bldtype` とID由来のハッシュで少し揺らす
  - `deck` は指定高さに1ブロック厚の床板（下は空洞→歩ける・通り抜けられる）
- 描画は**面カリング付きメッシュ**。ブロックごとのMeshやInstancedMeshは使わず、チャンクごとに1つの `BufferGeometry`
- テクスチャは**Canvasで生成した16×16のアトラス**（NearestFilter）。面の向き別の簡易陰影（上1.0／側面0.8・0.6／下0.5）を頂点カラーで付与。フォグとグラデーションの空
- メッシュ生成は1フレームあたり数msの予算制で分散（Phase 3でWeb Worker化）
- 描画距離は初期8チャンク、設定で変更可能

### 3.3 プレイヤー
- ポインターロックのFPS視点、WASD、Shiftでダッシュ、Spaceでジャンプ
- AABB衝突（幅0.6×高さ1.8、目線高さ1.62）、重力、1ブロックの段差はジャンプで登れる
- Spaceの素早い2連打でフライモード切替（Space上昇／Shift下降）
- 歩行速度 約4.3m/s、ダッシュ 約5.6m/s
- スポーン地点：JR宇都宮駅の東口側の歩行可能な地表。**必ず歩行可能な位置を探索して置く**（建物の中や水中に出さない）

### 3.4 HUD
- 十字カーソル、方位（北基準）、ローカル座標と緯度経度、FPS
- 最寄りのPOI名（30m以内）を画面上部にDOMテキストで表示
- 画面隅にライセンス表記を常時表示

### 3.5 デバッグAPI（`?debug=1` のときのみ公開）
`window.__ready`（初期チャンク生成完了でtrue）、`window.__teleport(x, z, yaw)`、`window.__stats`（チャンク数・頂点数・直近のチャンク生成ms・フレームms）。ヘッドレス検証用。

## 4. フェーズ計画

### Phase 0：データ検証
- `fetch-osm.mjs` でOSMを取得し、要素数（建物・道路・線路・POI）をレポート
- `build-world.mjs` の最小版でラスタを作り、`debug-preview.mjs` で俯瞰PNGを出力
- **合格基準**：俯瞰PNGで、JR宇都宮駅の線路・駅舎、東西の駅前広場、主要道路（大通り等）、鬼怒通り沿いのライトライン路線が現実の地図と対応して見える
- 問題（Overpass制限・座標ずれ・マルチポリゴン不備）はここで解決する

### Phase 1：歩ける世界（MVP・OSMのみ）
- 3.1〜3.5をすべて実装（高さはOSM由来、地面は平坦）、`tools/e2e/shot.mjs` を作成
- GitHub Pagesにデプロイ可能な状態（相対パス確認）
- **合格基準**
  - `python3 -m http.server` で起動し、初回ロードが実機で10秒以内（ヘッドレスではデータサイズと生成時間で代替評価）
  - 駅→駅前広場→大通りを歩いて、道・建物・線路が連続し、壁抜け・床抜けが起きない（衝突テストで確認）
  - 主要地点（駅東口、駅西口、大通り、鬼怒通り）の `shot.mjs` スクリーンショットが、現実の位置関係と整合している
  - 実機FPS・スマホ動作は **ユーザー確認事項**として報告に記載

### Phase 2：精度と遊びの追加
- PLATEAUの建物高さを取り込み、OSMより優先（`build-world.mjs` にオプション追加）
- ブロックの破壊・設置（ホットバー、簡単な材質選択）。編集差分は**IndexedDB**にチャンク単位で保存
- ミニマップ（Canvas 2D、Mキーで拡大）
- POIメニューからのテレポート（駅東口・西口、ライトライン停留場、餃子通り周辺など。OSMの名称検索で座標を確定し `world.json` に格納）
- タッチ操作（左：仮想ジョイスティック、右：視点ドラッグ、ジャンプボタン）
- 昼夜サイクル

### Phase 3：仕上げ（任意）
- 国土地理院DEMによる緩やかな起伏
- メッシュ生成のWeb Worker化
- ライトライン（LRT）が路線上を走るアニメーション（OSMの `railway=tram` の線形に沿って移動）
- 駅舎・ペデストリアンデッキ・ランドマークの手作りボクセル装飾

## 5. ライセンス・法務
- OSMデータ：ODbL。「© OpenStreetMap contributors」表記必須。加工済みラスタを公開リポジトリに置く場合は出典と再生成手順を明記
- PLATEAU：出典表記（CC BY 4.0／政府標準利用規約準拠）
- 「Minecraft」の商標・アセットは使用しない。アプリ名・アイコン・UIも独自のもの

## 6. 判断指針
- **精度より動くこと**を優先。完全一致より、歩いて「あの辺だ」とわかることを重視
- OSMの欠損（高さ・幅など）は既定値で埋め、`docs/decisions.md` に採用ルールを書く
- 性能不足のときは、まず描画距離・面カリング・メッシュ更新頻度で調整し、見た目の削減は最後
- 新しい依存は追加しない。必要な場合は理由を書いてユーザーに確認
- 仕様と実現性が衝突する場合（例：高架下の道路と床板の重なり）は、歩ける・落ちないを優先

## 7. 既知の落とし穴
- OSMのmultipolygon relationは外周・内周の向きと順序が不揃い。ring組み立てを堅牢に
- 緯度経度→ローカルm：`x = (lon-lon0)·cos(lat0)·111320`、`z = -(lat-lat0)·110540`（南北が反転しないこと）
- Uint8の高さはクランプしないとオーバーフローする
- チャンク境界の面カリングは隣接チャンクを参照する（未生成なら生成して参照。空気扱いにしない）
- 高架（deck）とその下の道路は同じ列にある。列ごとに「地表」「床板」「建物」を独立に評価
- three.js の import は importmap で `public/vendor/` を指す。CDN直リンクにしない
